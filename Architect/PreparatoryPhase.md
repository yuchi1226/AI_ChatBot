# 規格書：準備階段 – 系統提示詞注入與結構化建構

| 文件版本 | 1.0 |
| :--- | :--- |
| 撰寫日期 | 2026-08-24 |
| 目標框架 | Python Gradio (>= 4.0 / 5.0) |
| 核心目標 | 準備階段（③、④）：注入系統級指令 & 拉取當前模式（System Prompt）& 返回結構化 Prompt。 |

---

## 1. 概述
本規格定義核心調度器（Agent Harness）在處理使用者請求之前，必須完成的**系統提示詞準備階段**。此階段負責載入目前執行模式所需的系統級指令，並將其組裝為結構化提示詞（System Prompt），作為後續大語言模型推論的基礎上下文。該結構化提示詞包含角色定義、可用工具宣告、安全紅線、目前日期等關鍵元資訊，確保模型行為一致、可控且安全。

## 2. 前置條件
- 核心調度器已接收前端傳遞的工作階段識別碼（Session ID）和使用者輸入（含預處理後的上下文檔案）。
- 系統提示詞快取（System Prompt Cache）可用，且已預先載入所有模式範本。
- 目前系統時間可取得（用於注入目前日期）。

## 3. 詳細步驟

| 步驟編號 | 動作 | 負責元件 | 描述 |
|---------|------|----------|------|
| ③ | 拉取目前模式 | `Harness` → `System` | 根據工作階段設定或全域設定，向系統提示詞快取要求目前執行模式（如 `default`、`coding`、`research`、`safe` 等）對應的提示詞範本。 |
| ④ | 返回結構化 Prompt | `System` → `Harness` | 快取回傳一個結構化的提示詞物件（或字串範本），其中包含四個核心部分：**角色**、**工具定義**、**安全紅線**、**目前日期**。回傳值需帶有版本號或雜湊值，便於追蹤變更。 |
| 內部 | 參數填補 | `Harness` | 將目前日期（ISO 8601 格式）動態注入到提示詞中的 `{{current_date}}` 佔位符。如有其他動態參數（如使用者地域、語言偏好），一併填補。 |
| 內部 | 組裝完整請求 | `Harness` | 將填補後的系統提示詞與歷史對話記錄、目前使用者提問拼接，形成完整的模型輸入承載，準備發送至大語言模型（步驟⑤）。 |

## 4. 資料結構定義

### 4.1 系統提示詞範本（快取回傳）
```json
{
  "template_id": "sys_v3.2.1",
  "mode": "default",
  "content": {
    "role_definition": "你是一個智慧助理，具備專業、客觀、樂於助人的特質...",
    "tool_definitions": [
      {
        "name": "web_search",
        "description": "搜尋網際網路資訊",
        "parameters": { "type": "object", "properties": { "query": {"type": "string"} } }
      }
      // ...更多工具
    ],
    "safety_guardrails": "禁止輸出違法、暴力、色情內容；對不確定的資訊須誠實告知，不可捏造事實...",
    "current_date_placeholder": "{{current_date}}"
  },
  "metadata": {
    "updated_at": "2026-08-20T10:00:00Z",
    "version": "3.2.1"
  }
}
```

### 4.2 最終產生的系統提示詞（填補後）
```text
你是一個智慧助理，具備專業、客觀、樂於助人的特質。
目前日期：2026-08-24（UTC+8）。
可用工具如下：
- web_search: 搜尋網際網路資訊，參數 query (string)
...
安全紅線：...
```

### 4.3 完整請求承載（發送給 LLM）
```json
{
  "session_id": "sess_abc123",
  "messages": [
    {"role": "system", "content": "<填補後的系統提示詞>"},
    ... // 歷史對話（使用者/助理交替）
    {"role": "user", "content": "使用者目前提問"}
  ],
  "tools": [ /* 工具定義列表（與系統提示詞中的工具定義一致，但以 OpenAI 格式或 DeepSeek 專用格式傳遞） */ ],
  "temperature": 0.7,
  "max_tokens": 4096
}
```

## 5. 異常處理與降級策略

| 異常場景 | 處理方式 |
|---------|----------|
| 系統提示詞快取無法使用或逾時 | 使用內建的預設提示詞（硬編碼備援），並記錄警告日誌，觸發監控警示。 |
| 範本中缺少必要佔位符（如 `{{current_date}}`） | 自動在末尾附加「目前日期：{實際日期}」，確保資訊完整。 |
| 工具定義格式錯誤或版本不相容 | 記錄錯誤並回退至無工具模式（僅角色定義+安全紅線），通知前端降級。 |
| 安全紅線內容為空 | 採用全域預設安全規則（從設定中心載入），杜絕無防護狀態。 |

## 6. 效能與快取策略
- **快取命中**：系統提示詞範本按 `mode` 鍵值快取於記憶體中，TTL 為 5 分鐘或直至範本版本變更（透過版本號判斷）。
- **動態注入**：僅替換佔位符，避免重複解析範本，時間複雜度 O(1)。
- **大小控制**：系統提示詞總長度（角色+工具+紅線）不得超過 8K tokens（含佔位符），超出時自動截斷工具描述或精簡角色定義，確保不超過模型上下文視窗的 30%。

## 7. 安全考量
- **提示詞注入防護**：系統提示詞中的佔位符必須經過跳脫（escape）處理，使用者輸入的內容絕不可直接拼入系統提示詞，僅透過 `messages` 中的 `user` 角色傳遞。
- **敏感資訊脫敏**：目前日期等系統資訊僅用於上下文，不包含任何內部識別碼或機密參數。
- **稽核日誌**：每次拉取範本及最終產生的系統提示詞（完整內容）需記錄到稽核日誌（經脫敏處理），用於合規審查。

## 8. 測試驗證點
| 測試案例 | 預期結果 |
|---------|----------|
| 預設模式載入 | 回傳包含所有必要欄位（角色、工具、紅線、日期）的提示詞。 |
| 日期佔位符替換 | 最終提示詞中 `{{current_date}}` 被正確替換為目前日期。 |
| 工具定義遺漏 | 系統自動加入空工具列表，並正常回傳提示詞。 |
| 快取逾時 | 觸發備援預設提示詞，服務不中斷。 |
| 超大範本截斷 | 總長度控制在閾值內，無截斷錯誤。 |

## 9. 介面定義（Harness ↔ System Cache）

**請求**
```
GET /system-prompt?mode={mode}&version={optional}
Headers: X-Session-ID: {session_id}
```

**回應（成功）**
```
Status: 200 OK
Body: 如 4.1 所示 JSON
```

**回應（失敗）**
```
Status: 503 Service Unavailable
Body: {"error": "cache_unavailable", "fallback": true}
```
